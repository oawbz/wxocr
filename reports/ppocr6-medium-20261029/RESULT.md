# PP-OCRv6 medium 独立容器实测（2026-10-29）

按最后要求，以**单模型实例、单请求、CPU 限 1 核、4GiB 容器内存、4090 GPU 推理**比较。线上服务未修改，测试容器已停止，镜像与权重保留以便复测。

在本批样本中，PP-OCRv6 medium 的通用 1280 检测配置有收益：相对当前高分模式，表格中位耗时从约 2.61 秒降至 1.37 秒，已核对字段均为 70/70；进程显存峰值从 906MiB 增至 1702MiB。它比当前快速模式的表格识别更完整，但该图上仍比快速模式慢一些。

耗时为热态单并发闭环测试的 P50/P95，包含上传、解码、预处理、推理和 JSON 回传，不生成预览图。每组运行 15 秒并等待末次请求结束。小图混合使用中文、票据和双栏三张图。

单实例各组均无请求失败、无识别文字稳定性检查失败；准确度采集每图每模式重复三次。当前模型验证完整结果摘要，PP-OCRv6 验证识别文字列表稳定性。未声称不同模型的完整 JSON 或置信度一致。

## 准确度口径

人工从图片核对了 24 张合成图及其旋转/退化变体，共182行、2464个规范化字符；没有把旧引擎的 `native_expected.json` 当作正确答案。样本有多个同源变体，不代表独立真实文档总体准确率。

逐行比较先统一 NFKC、忽略空白，再按最小编辑代价匹配，不考核阅读顺序。当前模型的两处不完整行是长英文行漏了一个 `I`，以及旋转双栏页脚被拆成两框。后者文字内容仍在，因此不能把行匹配计算出的9个编辑惩罚说成9个真实错字。PP-OCRv6 在这24张图上没有这两处问题。详细匹配和错例见 `accuracy-summary.json`。

原始表格直接上传2480×3506 JPEG；PP-OCRv6 自身方向分类将其转正。按相同的评价区域检查序号、姓名、出生日期、工作日期、“无”、退休日期和岗位各10格，共70格；日期按数字比较、忽略分隔符，其余统一空白/NFKC后严格比较。13组长数字是图片中的17位合成测试字符串，仅检查完整出现，不补位、不校验或更改内容。70/70不等于整页全文100%正确。区域和标准答案仅用于评价，不参与识别。

当前模型的候选框没有混入正式文字评分。额外将 UI 所显示的候选框一起拼入单元格时，当前快速为48/70、高分为63/70；这反映候选框可能补字，也可能重复文字。主表使用正式 `lines`，原始候选框完整保留。

## 环境和配置

服务器：新广视-AI服务器，物理 GPU1，RTX4090 24564MiB，驱动570.144。GPU上原有其他服务持续运行，测试不是独占GPU；三套单实例测试顺序执行，彼此不同时施压。短测数据不能替代长稳或容量验收。

当前模型使用线上同版本镜像 `wxocr-web:cuda-fragment-20261029`，单独创建 localhost:17676 测试容器，`engine_workers=1`、`max_concurrent_tasks=1`、模型常驻、启动预热，CPU配额1核、`GOMAXPROCS=1`、容器内存4GiB。私有 Token 始终保留服务器，未导出配置。

PP-OCRv6 使用 `paddlepaddle-gpu=3.3.0`、`paddleocr=3.7.0`、`paddlex=3.7.2`，Paddle静态GPU推理；未启用TensorRT或FP16。检测和识别模型显式为 `PP-OCRv6_medium_det`、`PP-OCRv6_medium_rec`。开启文档方向和文本行方向分类，关闭文档展平。模型常驻，启动预热；OpenCV、Paddle CPU、OpenBLAS、OMP、MKL线程均设为1，容器CPU配额1核、内存4GiB。

默认检测实际参数为 `limit_side_len=64, limit_type=min, max_side_limit=4000`；1280配置仅统一改为 `limit_side_len=1280, limit_type=max`，无图片专用坐标、内容修补或字段补全。测试进程 Paddle 分配器上限6000MiB，避免侵占线上显存；单实例两配置均未触发上限。

实下载权重：检测59.09MiB、识别72.92MiB，另有两个方向分类模型各约6.4MiB。显存还包含CUDA上下文、工作区和缓存，不能把进程显存当作模型权重大小。

## 并发探索和边界

此前完成了8路初步探索；旧的Python/OpenCV/BLAS线程设置影响结果，默认原图大图还在6000MiB分配器上限下失败3次。8独立进程启动触发总GPU23800MiB保护，已停止；4进程×2实例的扩展按用户后续要求中止。**本次最终优化配置的8路能力未验收，不能从单请求成绩外推。**早期原始数据单独保留，不作为这次单实例结论。

当前可确认的是：PP-OCRv6 medium + 通用1280检测，在本批样本的单请求质量/耗时上有价值，资源开销约为当前实例的1.9倍显存、1.6倍内存。继续扩大真实文档样本比立即替换线上更能判断收益。
